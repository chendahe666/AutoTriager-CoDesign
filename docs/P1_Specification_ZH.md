# AutoTriager P1：故障分析与人类核查规格

状态：用户已确定交互边界、模型方向、语言、等待预期和本地演示方式；本轮更新文档，没有开始实现。实际 API 额度、模型版本和数据兼容性仍待技术核验，见第 9 节。本文不将设计或测试目标描述为已实现成果。

## 1. 已确认的目标与边界

**核心 P1：加载选定系统的故障案例，调用已有算法完成分析。**

本次课程交付将核心 P1 与必需的结果／证据展示结合，通过 Streamlit 提供一个最小的人机协作功能：

选择案例 → 运行分析 → 打开原始证据 → 接受／拒绝／标记待核查，并填写理由。

- 目标用户：需要检查故障线索的值班开发人员和系统可靠性工程师。课程演示验证这个使用流程，不宣称已经完成真实用户研究。
- 使用环境：离线故障资料；只读分析，不操作生产系统。
- 初始范围：一个系统、少量真实案例、一个已有分析方法。
- 输出：候选组件、可能原因、对应证据、信息缺口。
- 不足时：保留有支持的观察或候选，允许原因未确定。
- 本次不做：PR 审查或归因、多系统、开放式聊天、复杂多 Agent、自动修复。
- 后续功能：交互式组件比较和连续追问留在 Challenge 3；本次反馈保留于会话，不实现长期历史调查平台。
- 模型：优先使用 Gemini API 免费层，不产生额外付费；具体可用模型待账户与兼容性核验。
- 语言：中英文可切换的国际化界面。
- 等待预期：先允许几分钟，根据真实试跑再决定是否优化速度。
- 交付：在用户电脑上本地运行 Streamlit。
- 仓库：AutoTriager-CoDesign，按用户决定改为公开。

## 2. 使用流程与页面行为

| 步骤 | 页面与操作 | 预期行为 |
|---|---|---|
| 1. 选择 | 从预先登记的案例中选择一项 | 展示案例标识、系统、题目要求、调查窗口和数据可用情况 |
| 2. 确认 | 查看本次分析范围后点击分析 | 固定本次输入与配置；不能在运行途中悄悄改变案例 |
| 3. 等待 | 显示读取、处理、分析或校验等实际状态 | 防止重复点击产生相同付费请求，不显示虚假的完成百分比 |
| 4. 查看 | 显示结果与局限 | 区分候选、观察和未确定的原因；不给无依据的置信度百分比 |
| 5. 核查 | 打开某条证据 | 显示原始片段、时间、组件和来源；计算结果同时显示计算范围与方法 |
| 6. 判断 | 选择接受、拒绝或待核查，并填写理由 | 记录到当前分析结果；说明反馈代表用户判断，不是客观标准答案 |
| 7. 切换或重试 | 选择另一案例或重新执行 | 生成新的运行标识；旧输出与旧反馈不得冒充新结果 |

第一版采用预登记案例，便于保证数据结构和可复现性；任意文件上传与自由修改调查窗口不是当前已承诺功能。若用户希望加入，需要重新评估范围。

### 国际化实现约定

中英文切换是用户已确认需求；以下为落实该需求的技术约定，可在评审中调整：

- 界面标签、操作按钮、状态、错误提示和反馈选项使用统一翻译词典，不依赖模型实时翻译。
- 切换界面语言保留当前案例、证据和反馈，不自动调用模型或重跑诊断。
- 新分析按启动时选定语言生成说明，并记录该次输出语言。切换界面语言后已有说明保留原文，明确标注语言；如需另一语言的重新分析，由用户显式触发。
- 组件标识、文件名、证据编号和原始记录不翻译。反馈原文不自动改写。
- 本次支持中文和英文，结构允许以后增加语言，不因此承诺首版支持更多语言。

## 3. 输入与数据约定

以下是拟定的接口要求，我可以在不改变用户目标的前提下依据真实数据完善字段命名和结构。

| 输入 | 要求 |
|---|---|
| 案例信息 | 唯一案例标识、所属系统、原始题目、题目要求输出的字段 |
| 调查范围 | 起止时间、原始时区与单位；保留转换信息 |
| 原始记录 | 所选系统实际提供的指标、调用追踪和日志，不假设所有模态都有 |
| 参考记录 | 保留已有算法确实需要的基线时段；不能只为减小体积而任意截断 |
| 运行配置 | 算法版本、模型配置、数据版本和调用限制 |

Bank 是第一候选，OpenRCA 是拟用数据来源，EviRCA 是拟复用方法。三者兼容性及实际可获取范围仍待验证。先读取真实样本、核对既有方法，再冻结选择。

组件与时间范围由确定性代码校验。故障数量仅在题目本来提供时使用，不从答案中读取。不能预先固定每题只有一个故障；如只选单故障案例，应明确是本项目选取的子集。

标准答案单独用于评价，不进入模型上下文、检索索引、分析工具或由答案衍生的缓存。缺数据测试必须在受控副本中进行，并清除相关的完整数据缓存。

## 4. 分析分工与复用原则

1. **已有工具／Python：**加载和校验数据，转换时间单位，执行现有统计或异常处理，准备可回查的观察。
2. **检索：**依据组件、时间与来源标识取回有关记录，优先复用已有接口；不强制使用向量数据库。
3. **已有算法和 LLM：**根据取得的观察生成候选解释，比较支持与冲突信息，注明未知部分。
4. **输出检查：**检查结构、证据标识及来源范围；不把结构正确当成因果正确。
5. **人类：**回看原始材料，检查解释是否得到支持，并记录判断。

若现有方法已经处理检索和模型调用，不再重复搭建相同流程。库、文件结构、轻量存储和内部函数名由我自行选择并说明理由。

如需要修改原方法，应保存版本和修改清单。技术适配与完整论文复现分开陈述；若必须替换主要算法或数据源，先报告证据、备选方案及影响，由用户决定。

## 5. 输出与证据约定

一次运行至少关联以下信息：

- 案例与运行标识，输入范围，数据／方法／模型版本。
- 执行状态和结果完整性，二者分开表示。
- 候选组件、可能原因或明确的未确定状态。
- 支持或冲突的观察，以及它们的证据标识。
- 缺失的数据、未解决的问题和解释限制。
- 人类判断与理由，明确属于哪次运行。

每条可展示的证据应能定位到原始文件及行、日志或调用记录标识，并保留组件、时间、单位。若证据是聚合统计，应能说明由哪些原始记录和什么计算得到。来源定位不是证明因果，初始测试仍需要人工检查每项陈述。

题目要求的候选数量与字段应遵循题目，不根据已知答案构造候选。没有依据时不能为满足格式而补写原因；必答字段未解决时，评价仍按未答对处理。

## 6. 失败与不完整结果

| 情况 | 系统应该怎样表现 |
|---|---|
| 案例或必要字段无效 | 在模型调用前拦截，指出具体问题 |
| 调查窗口没有记录 | 说明没有可用证据；不能据此宣称没有故障 |
| 某类记录缺失 | 显示缺口；方法兼容时可用剩余记录分析，否则说明无法继续 |
| API 超时、认证或连接失败 | 标记分析未完成，保留已准备的证据；不产生伪造诊断 |
| 输出格式不正确 | 明确提示结果无效；受控修复或重试需记录，不能无限增加调用 |
| 引用不存在或越出范围 | 不将对应陈述呈现为已核实结论，显示校验问题 |
| 原因无法确定 | 运行可以完成，但结果应显示尚未确定，而不是执行失败或确定结论 |

没有数据时的兜底页面、预存报告回放和一次真正的模型分析应清楚区分。第一版不依赖伪造案例成功演示。

## 7. 验收与测试边界

工程验收关注：真实输入能进入分析流程、结果能显示、证据可回查、人类能核查、失败能正确表达。诊断正确率另行评价，不能把“程序跑完”写成“定位正确”。

沿用计划中的 8 项检查，并增加第 9 项国际化检查：真实案例 A、切换案例 B、时间与组件对应、证据回查、人类反馈、缺数据、无效引用、模型调用失败，以及中英文切换。语言测试检查静态文本覆盖、状态保留、来源标识不变，以及切换语言不会自动增加模型调用。测试的预期在查看输出前记录；实际失败不得删去。

至少争取两个不同的真实案例：一个用于调试，另一个检查切换和硬编码。具体题目由数据检查确定，不让用户手工猜选。若无法取得第二例，应报告受限范围，不能声称已经验证多案例支持。受控异常测试不能作为新增真实事故计数。

所有显示引用可回查、没有捏造原始记录，是验收目标而非现状。使用官方评分器前核对本版本评分逻辑；少量案例的结果不代表生产准确率或用户效率提升。

本次结束应能提供：实际运行应用、依赖及数据说明、测试记录、真实截图、方法复用与修改清单、约 10 页作业 PPT。公开部署不由“可供审查”自动推导，交付方式见待决定项。

## 8. 我可以自主完成，以及应何时交回用户

**当前计划阶段可自主完成：**审查文档与公开方法，核对字段、接口和许可证，找出技术风险，提出验收样例与实现选项。计划阶段不据此启动应用开发或付费模型调用。

**进入实现阶段后可自主完成：**在已确认范围内写代码、整理依赖、建立证据索引、处理状态、运行测试、调试、选择低风险的内部实现方式，并记录验证结果。

**需要交回用户决定：**主要目标改变、数据集或主要算法替换、产生额外付费、超出本项目公开记录范围的数据发送、改为公网部署，以及最终课程提交。公开本次仓库已获得授权，不重复确认。

以下不要求用户现在决定：JSON 字段名、数据库选择、统计计算代码、具体案例编号、缓存键、异常类、测试框架、Agent 数量。需要专业验证的问题先由我调查；只有涉及目标和代价的取舍才提交用户。

## 10. 导师与 reviewer 复核结论

这份规格将用户任务、工具计算、模型解释、人类核查和测试逐项连接，符合本次作业要求。数据与方法可运行性、Gemini 实际免费额度仍待验证。国际化增加了一项明确的功能与测试，但不需要因此引入额外模型或代理。

用户的产品决定已记录，继续处于计划阶段。下一步可以开展不涉及付费调用的资料与配置核验；应用实现尚未开始。若免费路径不能满足已有算法，需要带着具体原因和备选方案交回用户，不把资源假设当作保证。
